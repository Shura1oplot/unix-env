# Описание проекта

## Назначение

Проект хранит переносимые файлы среды Unix и сценарии их установки и обновления на macOS и Linux.

## Цели

1. Поддерживать одинаковое пользовательское окружение на рабочих системах.

2. Не изменять файлы другого пользователя при запуске сценариев с правами `root`.

3. Сохранять простые сценарии с проверяемым поведением.

## Критерии выполнения текущей задачи

1. Сценарий `cleanup.sh` с отметкой `users-managed` работает на macOS и Ubuntu под Bash 5+.

2. Сценарий запускается без параметров и сразу выполняет очистку. По запросу владельца от 2026-09-23 параметры и режим просмотра удалены.

3. Сохраняется последняя установленная стабильная версия каждой ветки Python `3.x` и каждой основной ветки Node.js. Исключения для текущих интерпретаторов, виртуальных окружений и псевдонимов fnm удалены.

4. Очистка кэшей использует штатные команды uv, npm и Homebrew; на Ubuntu также выполняется очистка системного кэша APT через `sudo`.

5. Проверки наличия команд отсутствуют. Ошибки команд завершают сценарий с ненулевым кодом. Проверки с подставными командами подтверждают отбор версий без реального удаления.

6. Обязательные проверки Bash завершаются без ошибок.

7. Окружение полностью настроено владельцем. Сценарий использует Bash 5+, GNU sort под именем `sort`, uv, fnm, npm и Homebrew без проверок и выбора альтернативных команд. ОС определяется только для выбора очистки APT.

8. Номера версий разбиваются на именованные части через `read`. Сортировку выполняет `sort -V`; регулярные выражения и `BASH_REMATCH` для выделения веток не используются.

## Ограничения

1. Значение переменной `HOME` не изменяется вызывающим процессом.

2. Владелец отвечает за выбор пользователя при запуске. Проверка прав удалена; системная очистка APT использует `sudo`.

3. Удаление Python может нарушить виртуальные окружения, а удаление Node.js удаляет глобальные пакеты этой версии. README описывает это ограничение; поиск зависимостей по всему диску не входит в задачу.

4. Пользовательские документы, проекты, общие каталоги кэшей и системные файлы напрямую не удаляются. В задаче очистки сценарии установки и обновления не изменяются.

## Обновление OpenClaw

1. Логика обновления находится непосредственно в `update.sh` с отметкой users-managed и работает на macOS и Ubuntu под Bash 5+.

2. При наличии fnm регулярное обновление предполагает, что OpenClaw уже установлен через npm в его окружении. Первоначальный перенос самостоятельной установки выполняется отдельно. После выбора Node через `fnm` пакет переносится общим блоком npm, команда выбирается через `PATH`. Служба пересоздается с актуальным исполняемым файлом Node. Версия Node не фиксируется в коде сценария.

3. Общий перенос и обновление npm-пакетов не содержат исключений для OpenClaw. Отдельные блоки останавливают его службу до изменения пакетов, выполняют миграции состояния и запускают службу на выбранной Node. При переносе в fnm версия пакета определяется общей политикой npm. Если пакет отсутствует в выбранной Node, сценарий завершается с ошибкой до миграций и запуска службы. Без fnm используется штатное обновление OpenClaw. Служба недоступна во время обновления пакетов.

4. По запросу владельца от 2026-09-23 первоначальный перенос, сохранение и сравнение путей запуска, удаление прежней команды, резервное копирование и архивирование исключены из регулярного обновления. Каталоги старых версий Node сохраняются.

5. Ошибки npm, `fnm`, установки, миграций и запуска службы завершают сценарий с ненулевым кодом. Автоматический возврат старой программы после миграции базы не выполняется.

6. Изолированные тесты проверяют перенос, порядок команд, пустой перечень npm-пакетов, пути с пробелами и ошибки. Реальные программы и службы при тестировании не обновляются.

7. Переменная `HOME` не изменяется. Действующая политика разрешения установочных сценариев остальных npm-пакетов сохраняется. Обновление приложения OpenClaw для macOS не входит в этот блок.

Проверка 2026-09-23: 31 изолированный сценарий из `tests/test-update-openclaw.py` прошел на macOS после сокращения. Проверены выбор команды через `PATH`, порядок остановки и запуска службы, отсутствие первоначального переноса и ошибки команд. Проверки Bash и Python прошли. Эта редакция на Ubuntu не запускалась. Реальные пакеты и службы не обновлялись.
